# Proposal: USD costs on `pig_proxy` inference spans

**Status:** the pure estimator/catalog-decoding increment, logical inference-span wiring, and fast failure retry scheduling are implemented. No cache restart retention yet. No external network was used for implementation.

## Implemented estimator

`pig_proxy/model_catalog.estimate(catalog, provider, model, input_tokens, output_tokens, cached_input_tokens)` returns `Unknown`, `UnknownTier`, `InputOnly`, `OutputOnly`, or `Complete(input, output, total)` in USD. Counts are optional; absent cached count means zero cache, negative counts invalidate usage, and negative rates leave the affected side unknown. Zero usage needs no rate. Cached usage is clamped to the inclusive input total and falls back to regular input price when no cache rate exists.

Catalog decoding qualifies models.dev model keys with the outer provider, including vendor-prefixed reseller model IDs, so rates cannot leak across providers. The estimator never uses bare aliases. Context tiers use the actual nested `tier: {type: "context", size: ...}` schema: the highest threshold strictly below input usage applies. Missing input usage or unsupported/incomplete tier conditions produce `UnknownTier`. Tier prices may be partial. Existing metrics `cost_usd` behavior is unchanged.

Tests use external JSON fixtures and a centralized pricing harness. Final validation passed: `mise run build`, `mise run test` (1,005 tests, including 239 proxy tests), and proxy `gleam format --check` / `gleam check`. The investigation findings below describe the pre-implementation baseline; remaining design sections cover subsequent trace/refresh work.

## Findings

- The `pig_proxy` runtime owns one supervised, named models.dev catalog actor. `runtime.start` starts it under a runtime-specific name and wires its immutable-name cache into the metrics emitter (`packages/pig_proxy/src/pig_proxy/runtime.gleam:65-96,114-135`). Reuse this actor/cache; do not add another catalog fetcher or actor.
- Config defaults to `https://models.dev/api.json` and a **1-hour (`3_600_000 ms`) refresh interval** (`packages/pig_proxy/src/pig_proxy/config.gleam:109-112`); the builder/env setting rejects non-positive values by reverting to that default (`config.gleam:169-179,353-362`). The actor schedules an immediate initial fetch, then schedules the next refresh **after each fetch completes** (`model_catalog.gleam:63-66,177-180,208-225`). Thus normal timer-driven requests do not overlap, although there is no explicit in-flight guard. Fetches run in spawned processes with a 30-second timeout; only HTTP 200 is accepted; failures log and retain the actor's previous catalog (`model_catalog.gleam:51,193-257`). There is no retry/backoff, `Retry-After`, or validator handling.
- Restart is a cache weakness: named actors restart under the same name, but catalog initialization publishes an empty catalog before fetching (`model_catalog.gleam:163-180`; runtime supervision in `runtime.gleam:19-26`). This also replaces the `persistent_term` cache entry, so last-good data does **not** survive an actor restart. Cache restart retention has not been implemented. `cached` otherwise reads a non-mailbox `persistent_term` snapshot (`model_catalog.gleam:96-102`; `pig_proxy_model_catalog_cache_ffi.erl:4-6`). A VM restart necessarily loses that cache.
- `ModelInfo` already decodes per-million-token input/output/cache-read/cache-write prices and context/output limits, plus tool/structured-output flags (`model_catalog.gleam:20-32,309-373`). It does **not** model long-context price tiers. `trace_metadata` captures optional input/output/cached token counts, merges late streaming usage without erasing earlier fields, and leaves absent values absent (`trace_metadata.gleam:33-68,93-127,215-237`). Buffered metadata comes from the response; stream metadata can arrive late (`trace_metadata.gleam:144-198`).
- The existing `cost_usd` helper returns a bare `Float`, treats missing prices as zero, splits cached input from uncached input, falls back to input price when no cache-read rate exists, and clamps cached tokens to input tokens (`model_catalog.gleam:119-154`). Its missing-price-as-zero contract is unsafe for span costs and should not be used unchanged. There is already a test explicitly pinning that behavior (`packages/pig_proxy/test/model_catalog_test.gleam:174-187`).
- Inference attributes are initially created from the requested model and the **first** routed target's provider (`server.gleam:220-227`). Actual fallback target/provider becomes known at commit; streaming records it in `SelectStream`, while buffered outcomes contain it in `execution.Committed` (`server.gleam:291-319,404-417`; `execution.gleam:71-104,238-280`). Response `model` is independently observed and emitted as `gen_ai.response.model` (`trace_metadata.gleam:144-198`; `pig_otel.gleam:240-263`). Cost lookup must not confuse first target with selected target, nor response model with requested model.
- `pig_otel.response_attributes` is pure and only maps known response metadata today (`packages/pig_otel/src/pig_otel.gleam:240-263`). `tracing.end_logical` applies those response attrs at logical inference completion (`packages/pig_proxy/src/pig_proxy/tracing.gleam:694-717`), which is a natural single place to append cost attributes. The lifecycle owner retains usage through logical completion for both buffered and streaming paths (`tracing.gleam:459-463,730-848`).
- Existing proxy tracing tests cover both Chat Completions and Responses, buffered and streaming/late usage, retry/fallback, failure, duplicate terminal, and death paths (`packages/pig_proxy/test/tracing_test.gleam:13-42,59-92,109-129,137-152,184-227`). The current shared tracing harness records starts/finishes but not attributes (`test/support/tracing_harness.gleam:23-43`). `pig_otel` has pure attribute matrix checks (`packages/pig_otel/test/support/harness.gleam:25-32`). The subscription example already has a real OTLP loopback receiver and typed attribute verifier suitable for end-to-end export checks (`packages/pig_proxy/examples/subscriptions/test/support/otlp_receiver.gleam:1`; `.../otlp_verify.gleam:1,224-226`).
- Prometheus metrics are a separate token/request aggregation path and estimate cost when rendering metrics from the same catalog; they are not OTel span attrs (`packages/pig_proxy/src/pig_proxy/metrics.gleam:1-12`; `metrics_endpoint.gleam`). This proposal changes inference spans only.

The `Latitude` source review supports the requested attribute keys and precedence: `gen_ai.usage.input_cost`, `.output_cost`, and `.total_cost` are USD; reported side values override catalog estimates by side, and a stated total controls total. It also warns that Latitude labels any submitted estimate as `provider_reported`, so Pig must document that these values are estimates despite Latitude's classification. Sending these recognized keys is the interoperability mechanism; a Pig-specific provenance attribute preserves the distinction in exported telemetry. See `knowledge/LATITUDE_CUSTOM_PRICING.md:17-23`. That note records live models.dev base rates for `openai/gpt-6-sol`, `gpt-6-luna`, and `gpt-6.1-sol` and says long-context rates are higher (`LATITUDE_CUSTOM_PRICING.md:5-15`); the catalog decoder currently has no tier selection metadata.

## Recommended design

### Pricing and span semantics

1. Add a pure estimator in `pig_proxy/model_catalog` (or a small adjacent pricing module) with an explicit result such as `KnownCosts(input: Option(Float), output: Option(Float), total: Option(Float))` versus `UnknownCost(reason)`. Never map missing model, missing usage, or missing required price to `0.0`. Preserve explicit zero token counts as known usage. Calculate input/output independently when that side's usage and price are known; calculate total only when both sides are known. Use `None` for attributes that cannot be estimated.
2. Keep the cached-token rule, with cached tokens treated as an inclusive subset of input. If cached count is present and a cache-read price exists, split input accordingly; without a cache-read price, use regular input price for cached tokens. If the cached count is absent, tentatively estimate all input at regular input price. Validate/clamp malformed cached counts and reject negative/non-finite prices in pure logic.
3. Append only known numeric OTel double attributes: `gen_ai.usage.input_cost`, `gen_ai.usage.output_cost`, and `gen_ai.usage.total_cost` (USD), plus a Pig-specific provenance attribute such as `pig.cost.provenance = "models_dev_estimate"`. Never label these estimates `provider_reported`; never add cost attrs when unknown. Support the relevant context-based tiers in the first accurate estimator (including threshold boundaries and cache rates), or omit estimates whenever tier applicability cannot be resolved. The current parser silently discards tier data; reusing it unchanged would underprice long requests.
4. Resolve the pricing provider from the **committed** target/provider, not the first configured candidate. Use the requested model as the pricing key because proxy strict routing and Latitude key estimates that way; do not silently switch to a response model that may identify a different billed model. Preserve the requested model as `gen_ai.request.model` and observed response model as `gen_ai.response.model`. Use exact provider-qualified IDs only for trace pricing; do not use existing bare aliases, whose collisions can select a different provider's rates.
5. Take a catalog snapshot once per inference and use that same immutable snapshot when terminal usage and selected target become known. This avoids a refresh in the middle of a long stream changing its effective estimate. The current global `cached(name)` can provide the snapshot, but capture must happen at request admission and the specific model lookup may happen at terminal. Avoid copying the entire catalog through every owner's mailbox: a practical implementation can pin the small set of pricing entries for routed providers/models, or retain a reference to an immutable catalog version. This detail needs checking against BEAM copying and cleanup behavior. This shares the actor's cache and adds no fetch or actor.

### Refresh behavior

- **Default recommendation:** change the default from the current 1 hour to **6 hours**, with deterministic/configurable ±10% scheduling jitter per runtime (sample once for each scheduled delay). Retain `PIG_PROXY_MODELS_REFRESH_MS` as the interval override. models.dev is reference pricing, not request-path data, so a multi-hour refresh keeps the source current without hourly synchronized polling by all deployments. Keep immediate initial refresh.
- Make refresh explicitly single-flight in actor state: ignore/coalesce `Refresh` while an operation is active; a completion clears the flag and schedules exactly one next attempt. Retain last-good catalog on all failures. Do not block actor mailbox/snapshots during I/O.
- Support conditional GET using `ETag`/`If-None-Match` and `Last-Modified`/`If-Modified-Since` when supplied. The existing shared transport accepts request headers and returns response headers (`packages/pig_transport/src/pig_transport/hackney.gleam:9-16,28-38`; `pig_transport_hackney_ffi.erl:15-23`), but models catalog code currently passes `[]` and discards headers (`model_catalog.gleam:235-257`). Handle 304 as successful not-modified, preserving catalog and validators. Do not assume every response supplies validators.
- **Implemented refresh behavior (supersedes the earlier no-fast-retry proposal):** retain the normal hourly success refresh interval. On failure, retry from 5 seconds with doubling exponential backoff and equal jitter in `[half, full]`, capped at the normal refresh interval. Success resets the failure count. A valid `Retry-After` delta-seconds or HTTP-date is a floor on the retry delay. The 30-second request timeout remains. Cache retention across actor restart is not implemented yet; restart still clears the catalog before fetching. Failures log once per attempt, without telemetry duplication. Pure policy tests supply deterministic jitter inputs; a gated loopback test proves an initial 503 is retried and the successful catalog is published. Validation passes: `mise run build`, `mise run check`, `mise run test` (1,012 tests including 246 proxy tests), the gated catalog retry test, and local subscription HTTP/OTLP acceptance (25 tests).
- On actor restart, initialize from the existing runtime-keyed persistent-term last-good value instead of publishing empty. This handles actor-only supervision restarts. Do not add disk persistence in the minimal change; document that VM restart starts empty pending immediate refresh. An optional durable/on-disk cache adds format, freshness, and corruption policy and is outside initial scope.

The six-hour default, jitter, conditional requests, backoff, and retaining the in-VM cache are recommendations, not current behavior. This increment retains the current refresh behavior and implements only typed estimation, selected identity, a request-scoped pricing projection, and logical inference cost attributes; refresh hardening can follow without changing pricing semantics.

## Implemented trace wiring

At request admission the server reads the runtime's cached catalog once and pins only provider/requested-model entries for routed targets. The opaque projection travels with the inference lifecycle, not the full catalog; no actor call or HTTP request is added. Buffered and streaming commits both record the actual committed provider on the logical span. Pricing always uses that provider plus the requested model. The observed response model and original request-model attributes remain untouched.

At logical completion the final merged usage is passed to the existing estimator. Known sides emit numeric double USD attributes `gen_ai.usage.input_cost` and/or `gen_ai.usage.output_cost`; `gen_ai.usage.total_cost` is emitted only for a `Complete` estimate. Any emitted estimate includes `pig.cost.provenance=models_dev_estimate`. Unknown sides, unknown providers/models, absent usage, and unresolved tier pricing stay omitted. These attributes are added only to the logical inference span, never HTTP attempt spans; existing telemetry/logging behavior is unchanged. This applies equally to buffered Responses/Chat Completions and streaming final/trailing usage. The selected provider also replaces the initially unknown `gen_ai.provider.name`, so fallback spans do not retain first-target identity.

## Test coverage and remaining plan

Implemented tracing checks compare the exact emitted cost/provenance attribute set across both APIs and buffered/SSE-parsed usage, including zero, partial, missing usage, unknown identity, and response-model mismatch. The local subscriptions acceptance serves a synthetic models.dev catalog, waits for priced metrics readiness, and verifies OTLP double-valued input/output/total costs and provenance on all four real HTTP API/stream combinations. It also rejects cost attributes on HTTP spans and rejected requests. Warm-up requests are allowed to remain unpriced because they can begin before initial catalog publication.

Validation: `mise run build`, `mise run check`, `mise run test` (1,006 tests, including 240 proxy tests), and `mise run test-integration-subscriptions` (25 tests plus HTTP/OTLP/shutdown acceptance) pass. A separate `test-integration-otel` task was attempted but is blocked by the environment's missing C compiler; the subscription OTLP acceptance uses the real SDK/exporter and passes.


- Pure estimator cases: known regular input/output; cache-read split; cache rate absent fallback; explicit zero token counts; missing input/output counts; one missing side price (other side remains known, total unknown); unknown model; partial catalog entry; cached > input and negative counts; invalid/negative price; no false zero. Add fixture pricing for regular and cache rates and assert exact dollars with float tolerance.
- Catalog parser cases using externalized fixture JSON: integer/float prices, missing `cost`, partial cost fields, cache fields, limits, unknown extra fields, and context-tier parsing/threshold selection. Unsupported tier kinds must not silently become base-rate estimates.
- Lifecycle attribute matrices: both APIs × buffered and stream; stream usage absent initially then present in terminal/trailing frame; explicit zero; missing/partial pricing; unknown model; late response-model identity; selected fallback provider differing from requested/first target; upstream failure/cancellation. Assert absent costs are omitted and provenance is `models_dev_estimate` only when at least one estimate is emitted. Keep tests value-in/value-out and fixture-driven per `knowledge/TESTING_STRATEGY.md:13-27,34-68,138-173`.
- Extend the tracing test recorder/harness to capture attributes at logical-span finish and verify span cost values through existing fallback, buffering, streaming, and terminal paths. Add a focused SDK/OTLP integration check using the subscription example's loopback collector to verify numeric AnyValue type, exact key names, and USD values survive OTLP. Do not rely on a remote collector or real models.dev calls.
- Refresh actor checks should use an injected deterministic fetch/scheduling boundary if actor behavior is tested; test parsing and retry-decision policy purely. Avoid sleeps and network mocks in normal unit tests, as required by `knowledge/TESTING_STRATEGY.md:16-27,163-181`. - Implementation acceptance: `mise run build` (must pass with warnings as errors per project instructions), `mise run test`, and the applicable `packages/pig_otel/fixtures/sdk_recording/run.sh` / local OTLP validation. Build, unit tests, and local subscription OTLP acceptance have been executed for the implemented increments; refresh-specific tests remain future work.

## Unresolved policy choices

1. Should the `total_cost` attribute be emitted only when both sides are estimable (recommended), or when either side is known with the unknown side implicitly excluded? The latter risks presenting an incomplete sum as a total.
2. Should requests with cached-token usage but no cached-token count assume no cached tokens (recommended) or mark input cost unknown? The former is an explicit base-price estimate, not exact cache billing.
3. **Settled for trace wiring:** requested model is the pricing key. The response model remains an independently observed semantic attribute and is not used as an implicit pricing fallback.
4. Does Pig add a generic cost provenance attribute, and what stable name/value is desired? Recommendation: `pig.cost.provenance=models_dev_estimate`; do not use an OpenTelemetry/Latitude provider-reported marker.
5. Is a six-hour default acceptable, or should compatibility preserve current hourly refresh? Proposed default can remain configurable, but its change should be documented.
6. Is memory-only last-good retention sufficient, or is persistence across VM restart required? Recommendation: no disk cache initially.
7. Unknown/unset providers will intentionally remain unpriced. Existing bare aliases can resolve collisions by last insertion (`model_catalog.gleam:286-299`); do not use them for trace-cost estimation.

## Implementation outline and scope

1. Implement typed, pure USD estimation, relevant context-tier decoding/selection, exact provider-qualified lookup, and fixture tests; add a new unknown-aware API without allowing existing missing-price-as-zero semantics into tracing.
2. Carry the committed target/provider and selected response/request model identity to logical inference finalization; snapshot the existing catalog once per inference.
3. Add cost/provenance attribute mapping to `pig_otel` or proxy tracing, then append at logical terminal after final metadata merge.
4. Extend proxy tracing matrix/recorder tests and loopback OTLP verification for sync/streaming and both APIs.
5. Harden the existing catalog actor (single flight, last-good restart preservation, conditional GET, polite bounded scheduling/backoff) without introducing a second actor or fetch path.

**Scope recommendation:** implement attributes only in `pig_proxy`, because it has the shared live catalog and the task concerns `pig_proxy` inference spans. Keep generic typed USD attribute helpers in `pig_otel` only if they are genuinely reusable and do not make `pig` direct-agent inference depend on models.dev. Do not change the whole `pig` agent tracing path, Prometheus metrics semantics, or Latitude integration. A future consumer-supplied pricing interface could generalize direct Pig inference separately.
